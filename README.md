# Сигнал — тренажёр для HR-специалистов малого бизнеса

Команда 3, KIB-03. Зарегистрированная тема — «Тренажер-детектор дипфейков для HR-специалистов малого бизнеса». Это самостоятельная минимальная реализация формата «интерактивный квиз с видео» для Блока 2.

## Запуск за минуту

Скачайте репозиторий (Code → Download ZIP), полностью распакуйте папку и дважды щёлкните по **index.html**. Все ролики, субтитры и логика находятся рядом с ним. Интернет, регистрация, сервер и установка программ не нужны. На GitHub Pages можно выбрать ветку с проектом и каталог /(root) в Settings → Pages.

## Как показать на защите

1. Откройте страницу и включите первый ролик. Английская озвучка сопровождается русскими субтитрами; под видео есть текстовое описание звука и изображения.
2. На уточняющий вопрос звучит прежняя реплика, а губы во время повтора неподвижны. Отметьте возможную подмену, а в качестве действия намеренно выберите отказ кандидату. Нажмите «Проверить ответ». Наблюдение верное, но система объяснит, почему стоит провести повторную проверку.
3. Во втором звонке после помех кандидат отвечает по существу. Выберите технический сбой и продолжение интервью с обычной проверкой.
4. В третьем звонке есть лишь звук. Выберите нехватку данных и согласование повторной или альтернативной проверки.
5. Нажмите «Посмотреть результат». В этом примере получится **5 из 6**: 3/3 за наблюдения и 2/3 за действия. Нажмите «Пройти ещё раз», чтобы сбросить попытку.

## Задача и метрика

Небольшая компания (до 100 сотрудников) собеседует удалённых кандидатов. HR должен заметить повод для перепроверки и избежать необоснованного отказа из-за помех. В каждом из трёх учебных звонков отдельно оцениваются интерпретация и действие. Балл рассчитывается по заранее определённым ответам. Рабочий критерий успешного прохождения — 3 безопасных действия из 3. Для проверки образовательного эффекта нужен пилот: сравнить долю безопасных действий у тех же участников на сопоставимых новых кейсах до и после занятия. Данных такого пилота у этой версии нет.

## Основания

- [FBI IC3, бюллетень от 28.06.2022](https://www.ic3.gov/psa/2022/psa220628). В жалобах на удалённый найм упомянуты несовпадения голоса и движений во время интервью. Отсюда сценарий с повтором аудио. Жалобы не дают оценку доли мошенников среди кандидатов.
- [Mandiant M-Trends 2025, Executive Edition, с. 4](https://services.google.com/fh/files/misc/m-trends-2025-executive-edition-en.pdf), Банк источников **SRC-389**. Описано использование вымышленных или похищенных идентичностей для найма. Отсюда проверка по независимым сведениям.
- [Deloitte Insights, 2024, вводный кейс и рис. 1](https://www.deloitte.com/us/en/insights/industry/financial-services/deepfake-banking-fraud-risk-on-the-rise.html), Банк источников **SRC-534**. Пример подмены участников видеозвонка касается финансового мошенничества. Для HR переносим только принцип: картинка звонка сама по себе не удостоверяет личность.
- [KnowBe4, разбор происшествия](https://blog.knowbe4.com/how-a-north-korean-fake-it-worker-tried-to-infiltrate-us). Компания описала случай найма под чужой личностью после четырёх видеоинтервью. Это пример риска для процесса найма, а не подтверждённый случай подмены видео в каждом звонке.

## Выводы о запуске

1. [Product Hunt](https://www.producthunt.com/launch) выделяет подготовку страницы продукта как отдельную задачу. Для нашей страницы обещание формулируется через конкретную роль и действие: HR принимает решение после просмотра звонка. Проверяем, понимает ли человек задачу без устного инструктажа.
2. [Show HN](https://news.ycombinator.com/showhn.html) просит дать аудитории возможность попробовать продукт. Поэтому первый кейс доступен сразу. На этой площадке уместно собрать отзывы о работе интерфейса, а результаты разработчиков нельзя обобщать на HR.
3. [BetaList](https://betalist.com/submit) подходит для привлечения ранних пользователей. Для проверки ценности нужно отдельно пригласить HR малых компаний. Показатель пилота — доля безопасных действий на новых сценах. Внешний запуск и опрос в рамках сборки не проводились.

Отправная точка исследования — [обзор LaunchList](https://getlaunchlist.com/blog/product-hunt-alternatives). Критерии площадок сверены с их страницами. Доказательств готовности работодателей платить у проекта пока нет.

## Данные, угрозы и ограничения

| Актив и риск | Как устроена защита | Остаточное ограничение |
|---|---|---|
| Материалы кандидатов могут раскрыть личные данные | В комплекте только процедурная анимация, вымышленные диалоги и синтезированные голоса; поля загрузки нет | Произвольные записи кандидатов анализировать нельзя |
| Необоснованный отказ по внешности или помехам | Отдельный балл за действие; есть случаи технического сбоя и недостаточных данных | Правильный учебный ответ не удостоверяет личность |
| История ответов может раскрывать сведения о пользователе | Ответы хранятся только в памяти вкладки; в коде нет аналитики, сетевой отправки или постоянного хранилища | При перезагрузке прогресс теряется; хостинг при онлайн-запуске обслуживает обычные запросы браузера |
| Баллы могут быть завышены при повторении | Результат подписан как учебная попытка | Три фиксированных сцены можно запомнить. Оценка непригодна для аттестации |

## Проверки

В браузере воспроизведён полный сценарий с итогом 5/6. Первый WebM ролик запущен, у всех трёх проверено чтение длительности (около 12–13 секунд). В первом звонке верная оценка и ошибочное действие получили разные пояснения. Пустой ответ и ответ только на первый вопрос оставляют кнопку проверки недоступной. После повторного запуска выбранные ответы сбрасываются. Текстовую версию можно развернуть. Видео доступны также в MP4. Код не содержит форм ввода личных данных, сетевых API, cookies или внешних ресурсов.

## Разработка

Прототип собран с помощью ChatGPT/Codex. Учебные видео полностью синтетические. В браузере проверены воспроизведение WebM, отправка ответов и расчёт результата.
